# 하네스 엔지니어링 규칙 및 결함·오류 레지스트리 (Multi-LLM 공유)

> **목적**: 이 문서는 동네한권(`choise-hun/libtalk`) 단독 마스터 예비본을 여러 세션과 **서로 다른 고급 LLM 모델(구현 모델 ↔ 적대적 리뷰·테스트 모델)**이 교차 검증하며 완주하기 위한 **하네스 엔지니어링(Harness Engineering) 규칙 및 결함 누적 레지스트리**다.
> **필수 준수**: 새 세션을 시작하는 구현 AI와 Phase 단위 적대적 리뷰를 수행하는 리뷰어 AI는 작업 착수 전 반드시 [CLAUDE.md](../CLAUDE.md), [AI_작업_기록.md](AI_작업_기록.md), 그리고 이 문서를 먼저 읽어야 한다.

---

## 1. 운영 사이클 (Step 분리 커밋 + Phase 적대적 리뷰 루프)

1. **Step 단위 구현·검증·분리 커밋·Push**:
   - [상용 서비스 계획 §3](상용_서비스_계획.md)의 커밋 순서대로 한 번에 한 Step씩 구현한다.
   - 구현 직후 실제 격리 DB(`docker compose up -d --wait db`), 마이그레이션(`alembic upgrade head`), 테스트(`pytest -W error`), 앱 변경 시 타입·번들 검증(`npx tsc --noEmit`, `npx expo export --platform web`)을 실행해 통과를 확인한다.
   - 계약된 파일만 포함해 Step 커밋(`feat(...)`)을 생성한 뒤, [AI_작업_기록.md](AI_작업_기록.md)와 이 문서의 결함 레지스트리를 별도 `docs(harness): ...` 커밋으로 갱신하고 `origin/main`에 push한다.
2. **Phase 단위 타 LLM 적대적 리뷰(Adversarial Review) 및 테스트**:
   - 한 Phase가 끝나거나 주요 관문마다 **다른 고급 LLM 모델**이 적대적 리뷰어로서 코드·마이그레이션·테스트를 감사하고 공격 테스트를 실행한다.
   - 리뷰 과정에서 발견된 결함·경계 조건 누락·환경 오류는 즉시 수정 커밋으로 반영하고, 재발 방지를 위해 아래 **§5 결함 및 오류 하네스 레지스트리(`DEF-XXX`)**에 규칙으로 영구 등록한다.
3. **새 세션 컨텍스트 전환**:
   - 컨텍스트 오염과 피로를 막기 위해 Phase 검증 후 새 세션에서 다음 Phase를 시작하며, 새 세션의 AI는 [AI_작업_기록.md](AI_작업_기록.md)의 인계 블록을 읽고 즉시 이어받는다.

## 3. 실행 환경 및 도구 하네스 가드 (`H-ENV`)

| 규칙 ID | 하네스 규칙 | 상세 대응 방법 |
| :--- | :--- | :--- |
| **H-ENV-01** | **macOS `uv` 실행 경로 확보** | 로컬 macOS에 전역 `uv`가 없을 수 있다. `which uv`가 실패하면 `/opt/homebrew/bin/python3.12 -m venv /tmp/uvenv && /tmp/uvenv/bin/pip install -q uv`로 `/tmp/uvenv/bin/uv`를 준비한 뒤 `server/`에서 `/tmp/uvenv/bin/uv run ...`으로 실행한다. |
| **H-ENV-02** | **Alembic `env.py` 주소 단일화 & 로컬 `.env` 준비** | 계약 C5에 따라 `server/migrations/env.py`는 오직 `app.settings.get_settings().database_url`만 참조해야 하며, `env.py`나 `alembic.ini`에 별도 DB URL 문자열을 하드코딩하지 않는다. 로컬에서 `alembic` CLI를 직접 실행하기 전 루트에 `.env`(`cp .env.example .env`, gitignore 대상)가 있는지 확인하거나 `DATABASE_URL` 환경변수를 명시한다. |
| **H-ENV-03** | **비-DB 테스트 모듈 격리** | `test_auth_jwt.py`는 `app.state.engine`에 `do_connect` 감시자를 걸어 DB 연결 시도 자체를 실패(`AssertionError`)로 처리한다. `server/tests/conftest.py`의 자동 테이블 정리(`TRUNCATE`) 픽스처는 `NO_DB_MODULES = {"test_auth_jwt.py", "test_cors.py", "test_ready.py"}`를 건너뛰어 DB 없이 도는 테스트의 독립성을 보장한다. |
| **H-ENV-04** | **`pytest -W error` 경고 무관용** | 모든 pytest 실행은 `-W error` 플래그를 포함한다. pytest 9에서 deprecated된 `request.node.fspath` 대신 `request.node.path.name`을 쓰고, SQLAlchemy/Pydantic/datetime(naive datetime 금지) 경고가 0건이어야 한다. |
| **H-ENV-05** | **DB 연결 실패 재현은 로컬 즉시 종료 소켓(`refusing_db_url`) 사용** | 닫힌 포트(`127.0.0.1:1`)는 OS(특히 Windows)에 따라 타임아웃이 2초 이상 걸린다. `503 DB_UNAVAILABLE` 테스트는 `conftest.py`의 `refusing_db_url`(연결 즉시 `close()`하는 임시 소켓)을 사용한다. |

## 4. 아키텍처·보안·데이터 무결성 하네스 가드 (`H-ARCH`)

| 규칙 ID | 하네스 규칙 | 검증 방법 |
| :--- | :--- | :--- |
| **H-ARCH-01** | **전 테이블 RLS 활성화 및 정책 0개** | 모든 마이그레이션(`0001`, `0002`, `0003`)에서 테이블 생성 직후 `ALTER TABLE <name> ENABLE ROW LEVEL SECURITY`를 실행한다. `pg_class.relrowsecurity = true` 및 `pg_policies` 0개임을 테스트로 단언한다. |
| **H-ARCH-02** | **`run_db` 예외 경계 엄수** | `run_db`는 `OperationalError`·`InterfaceError`·`TimeoutError`만 `ApiError(503, "DB_UNAVAILABLE", ...)`로 바꾸고, `ApiError`나 `IntegrityError`(제약 위반)는 트랜잭션 롤백 후 그대로 다시 던져 호출자가 처리하게 한다. |
| **H-ARCH-03** | **트랜잭션 내 외부 I/O 절대 금지** | JWKS HTTP 조회, 외부 도서/도서관 API 호출, 이미지 파일 디스크 저장/EXIF 제거는 반드시 `run_db` 밖에서 수행한다. |
| **H-ARCH-04** | **소유자 식별(`sub`) 및 404 은닉** | 요청 본문·쿼리의 `user_id`는 무시하고 검증된 JWT `CurrentUser.id`만 사용한다. 타인 소유 개인 리소스와 존재하지 않는 리소스는 모두 동일한 `404 NOT_FOUND`로 응답한다. |
| **H-ARCH-05** | **서울 날짜/시각(`KST`) 단일 기준** | 모든 날짜(`today_kst()`)와 응답 타임스탬프(`now_kst().isoformat(timespec="seconds")`, `+09:00`)는 `app.common` 헬퍼를 사용한다. |

## 5. 타 LLM 적대적 리뷰(Adversarial Review) 체크리스트

Phase 단위 리뷰를 맡은 고급 LLM 모델은 단순 코드 읽기에 그치지 않고 아래 5가지를 직접 실행·공격하여 검증한다.

1. **계약 대조(Contract Audit)**:
   - 해당 Phase의 각 커밋(`git show --stat <sha>`)이 허용 파일 목록과 정확히 일치하는가?
   - 엔드포인트 경로·HTTP 상태 코드·응답 JSON 키·한국어 에러 문구(`message`)가 `06_기능_API_정의서.md` 및 계약서(`AUTH-1_계약서.md` 등)와 1글자도 빠짐없이 일치하는가?
2. **트랜잭션 & 동시성 공격(Concurrency & Atomicity Attack)**:
   - 연타/동시 요청 시 중복 행이 생기거나 `IntegrityError`가 500으로 노출되지 않고 계약된 멱등 응답(예: `ON CONFLICT DO NOTHING`)으로 처리되는가?
   - 쓰기 도중 예외 발생 시 부분 데이터가 남지 않고 완전히 롤백되는가?
3. **인증·권한·격리 공격(Auth & Isolation Attack)**:
   - 만료 토큰, 잘못된 `iss`/`aud`/`role`, `HS256`/`none` 알고리즘, 비-UUID `sub`, 탈퇴 계정(`status='withdrawn'`), 타인 리소스 ID 접근이 모두 계약된 상태 코드(401/403/404)로 차단되는가?
4. **스키마·RLS·마이그레이션 왕복 검사(Schema & Migration Audit)**:
   - `alembic downgrade base && alembic upgrade head`가 에러 없이 수행되는가?
   - 생성된 모든 테이블에 CHECK 제약, FK, 부분 UNIQUE 인덱스, RLS(`relrowsecurity = true`, 정책 0개)가 빠짐없이 걸려 있는가?
5. **테스트 무결성 감사(Test Integrity Audit)**:
   - 테스트가 실제 로직을 검증하는가? (가짜 성공 반환, 단언 누락, `pytest.skip`, 경고 무시 여부 점검)

## 6. 결함 및 오류 하네스 레지스트리 (Defect & Error Registry)

구현 및 적대적 리뷰 과정에서 발견된 결함·오류·잠재적 함정과 그 해결책을 누적 기록한다. 모든 후속 세션 AI는 아래 항목이 재발하지 않도록 주의한다.

| ID | 발견 시점 / Step | 구분 | 현상 및 원인 | 적용된 하네스 해결책 (재발 방지 가드) |
| :--- | :--- | :--- | :--- | :--- |
| **DEF-001** | Phase 1 / `AUTH-1-P2` | 환경 (`uv`) | macOS 로컬 환경의 기본 `PATH`에 `uv` 바이너리가 없어 `uv run` 직접 호출 시 `command not found` 발생 | **H-ENV-01**: `/opt/homebrew/bin/python3.12 -m venv /tmp/uvenv && /tmp/uvenv/bin/pip install -q uv`로 `/tmp/uvenv/bin/uv`를 구성해 `server/.venv`를 동기화·실행하도록 표준화 |
